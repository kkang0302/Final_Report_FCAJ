# Summary Report: "Cloud Architecture Battle 1"

### Event Objectives

- Validate core cloud architecture concepts under competitive pressure.
- Test speed and accuracy in solving system design scenarios.
- Encourage collaborative decision-making within teams.

### Event Format

The tournament featured an engaging competition style:
1. Two teams competed head-to-head.
2. The teams answered a series of cloud architecture multiple-choice questions.
3. The questions progressed from foundational topics to complex system designs.
4. Scores were calculated based on accuracy and response time, determining the winning team at the end of the rounds.

### Key Cloud Architecture Knowledge Gained

#### 1. Multi-Tier Application Design & Scalability
- Understanding the placement of public and private subnets to isolate resources.
- Deepened knowledge on configuring Application Load Balancers (ALB) and Auto Scaling Groups (ASG) to dynamic scaling based on CPU utilization or request count.
- Learning best practices for Multi-AZ deployments in Amazon RDS to ensure database high availability.

#### 2. Caching Strategies & Database Read Offloading
- Recognizing when to implement Amazon ElastiCache (Redis/Memcached) to store session states and cache frequent database queries.
- Distinguishing between Read Replicas (for scaling read traffic) and Multi-AZ deployments (for disaster recovery and high availability).

#### 3. Asynchronous & Decoupled Processing
- Utilizing message queues like Amazon SQS to buffer spikes in user traffic and prevent application overload.
- Integrating Amazon S3 event notifications with AWS Lambda for cost-efficient, event-driven serverless file processing.
